# Глава 3 - Структуры данных Python

## Часть 1. `list`, `tuple`, `dict`, `set`

**Таблица сложности операций:**

| Структура | Доступ | Поиск | Вставка | Удаление | Примечания |
|---|---|---|---|---|---|
| `list`  | O(1) по индексу | O(n)          | O(1) append | O(n) произвольное | Упорядоченная, изменяемая                           |
| `tuple` | O(1) по индексу | O(n)          | -           | -                 | Неизменяемая, хешируемая                            |
| `dict`  | O(1) по ключу   | O(1) по ключу | O(1)        | O(1)              | Упорядоченная (3.7+), изменяемая                    |
| `set`   | -               | O(1)          | O(1)        | O(1)              | Неупорядоченная, без дубликатов, элементы хешируемы |

### 1.1 Почему `dict`/`set` быстрее `list` в поиске

Под капотом `dict` и `set` - это хеш-таблицы: значение находится по хешу ключа/элемента напрямую, без перебора. `list` требует линейного просмотра, если не известна позиция.

### 1.2 Требования к хешируемости

Ключом словаря или элементом множества может быть только **неизменяемый и хешируемый** объект.

### 1.3 Когда что использовать

- **`list`** - когда важен порядок и возможны дубликаты, нужен доступ по индексу.
- **`tuple`** - когда данные не должны меняться (координаты, RGB, строка таблицы), либо нужен хешируемый ключ.
- **`dict`** - когда нужен быстрый доступ "по имени/ключу", а не по позиции.
- **`set`** - когда важна только уникальность и быстрая проверка вхождения, порядок не важен.

## Часть 2. Изменяемость и идентичность

### 2.1 `is` vs `==`

`==` сравнивает **значения**, `is` сравнивает **идентичность объектов** (один и тот же объект в памяти).

**Частая ловушка:** сравнение с `None` всегда через `is`, а не `==`.

### 2.2 Изменяемые (mutable) и неизменяемые (immutable) типы

| Изменяемые            | Неизменяемые                                        |
|--|--|
| `list`, `dict`, `set` | `tuple`, `str`, `int`, `float`, `bool`              |

### 2.3 Поверхностное и глубокое копирование

**Правило:** поверхностная копия копирует только верхний уровень контейнера - вложенные изменяемые объекты остаются общими (алиасинг). Глубокая копия рекурсивно копирует всё дерево объектов.

#### Исходный объект

```text
root
├── "a" ──► 1
└── "b" ──► list
            ├── 2
            └── 3
```

#### Поверхностная копия (`copy.copy()`)

```text
оригинал                 поверхностная копия
    │                            │
    ▼                            ▼
┌────────┐                  ┌────────┐
│  dict  │                  │  dict  │
└──┬──┬──┘                  └──┬──┬──┘
   │  │                         │  │
   │  └─────────────────────────┘  │
   │                                │
   ▼                                ▼
   1                         тот же самый list
                             ├── 2
                             └── 3
```

**Копируется только контейнер верхнего уровня.**
Вложенный изменяемый объект (`list`) **остаётся общим** для обеих копий (алиасинг).

### Глубокая копия (`copy.deepcopy()`)

```text
оригинал                     глубокая копия
    │                               │
    ▼                               ▼
┌────────┐                     ┌────────┐
│  dict  │                     │  dict  │
└──┬──┬──┘                     └──┬──┬──┘
   │  │                            │  │
   │  ▼                            │  ▼
   │ list A                        │ list B
   │ ├── 2                         │ ├── 2
   │ └── 3                         │ └── 3
   │
   ▼
   1
```

**Рекурсивно копируется всё дерево объектов.**
Каждый вложенный изменяемый объект получает **свою собственную копию**, поэтому изменения в одной структуре не влияют на другую.

### 2.4 Типичные ошибки с алиасингом

При создании многомерного списка (матрицы) с помощью оператора `*`, вы можете неожиданно получить **общие** вложенные списки.
В Python оператор * для списков не создаёт копии объектов. Он просто дублирует ссылки на уже существующий объект.

```text
[[0] * 3] * 3
     ↓          ↓          ↓
  [0, 0, 0] ← ссылка 1
  [0, 0, 0] ← ссылка 2   (тот же объект!)
  [0, 0, 0] ← ссылка 3   (тот же объект!)
```

```python
def add_tax(order):
    order["total"] *= 1.2
    return order
```

```text
order = {"total": 100}
    ↓
    │    Память
    ▼
┌─────────────┐
│ {"total": 100} │
└─────────────┘
    ↑
    │
add_tax(order) → передаётся ссылка (копия адреса)
    │
    │ (работаем с тем же объектом)
    ▼
┌─────────────┐
│ {"total": 120} │ ← объект изменился
└─────────────┘
    ↑
    │
print(order["total"]) → 120 (оригинал изменился)
```

### 3.4 `OrderedDict`

**Лирическое отсутпление**
_LRU cache (Least Recently Used)_

Представьте, что у вас есть **шкаф**, в котором помещается только **3 книги**.

Каждый раз, когда вам нужна книга, вы:
1. Ищете её в шкафу
2. Если её нет - идёте в библиотеку (это медленно)

Но в шкафу мало места. Когда вы приносите новую книгу, а места нет - **приходится выкидывать** какую-то старую.

**Вопрос:** какую книгу выкинуть?

## LRU

**LRU** = **Least Recently Used** (наименее недавно использованная)

Правило простое:
**Выкидывай ту книгу, которую брал в руки дольше всего назад.**

```text
                    ┌─────────────────────────────────────────────┐
                    │  LRU Cache (Least Recently Used)          │
                    │  with OrderedDict                         │
                    └──────────┬──────────────────────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────────────────┐
              │  Cache Operations                            │
              │  - Access key → move to end (most recent)    │
              │  - Add new key → append to end               │
              │  - When full → pop first (least recent)      │
              └────────────────┬───────────────────────────────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
          ▼                    ▼                    ▼
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│  GET operation   │  │  PUT operation   │  │  EVICT           │
│  key exists:     │  │  key exists:     │  │  cache full:     │
│  move_to_end()   │  │  update value,   │  │  popitem(last=   │
│  return value    │  │  move_to_end()   │  │  False) remove   │
│                  │  │  key missing:    │  │  oldest item     │
│                  │  │  append new      │  │                  │
└──────────────────┘  └──────────────────┘  └──────────────────┘
          │                    │                    │
          └────────────────────┼────────────────────┘
                               │
                               ▼
              ┌────────────────────────────────────────────────┐
              │  Order in OrderedDict                        │
              │  [oldest ... ... ... most_recent]            │
              └────────────────────────────────────────────────┘
```

## Часть 4. Comprehensions и вложенные структуры

### 4.1 List, dict и set comprehensions

Comprehension (генератор коллекций) - это синтаксический сахар в Python, который позволяет создавать новые коллекции (списки, словари, множества) из существующих итерируемых объектов, используя лаконичный и выразительный синтаксис

```text
                    ┌─────────────────────────────────────────────────────┐
                    │           COMPREHENSIONS IN PYTHON                │
                    │  Синтаксический сахар для создания коллекций      │
                    └─────────────────────┬───────────────────────────────┘
                                          │
              ┌───────────────────────────┼───────────────────────────┐
              │                           │                           │
              ▼                           ▼                           ▼
┌─────────────────────────┐ ┌─────────────────────────┐ ┌─────────────────────────┐
│  LIST COMPREHENSION     │ │  DICT COMPREHENSION     │ │  SET COMPREHENSION      │
│  [expr for x in iter]   │ │  {key: val for x in iter}│ │  {expr for x in iter}  │
└──────────┬──────────────┘ └──────────┬──────────────┘ └──────────┬──────────────┘
           │                           │                           │
           ▼                           ▼                           ▼
┌─────────────────────────┐ ┌─────────────────────────┐ ┌─────────────────────────┐
│  squares = [x**2        │ │  square_map = {x: x**2  │ │  unique_lengths =       │
│  for x in range(10)]    │ │  for x in range(10)}    │ │  {len(word) for word    │
│                         │ │                         │ │  in ["кот","собака"]}   │
│  [0,1,4,9,16,25,36,     │ │  {0:0, 1:1, 2:4, ...}   │ │  {3, 7, 4}              │
│   49,64,81]             │ │                         │ │                         │
└─────────────────────────┘ └─────────────────────────┘ └─────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         WITH CONDITION (FILTER)                             │
│  even_squares = [x**2 for x in range(10) if x % 2 == 0]                     │
│                                                                             │
│  1. Итерируем по range(10)                                                  │
│  2. Проверяем условие: x % 2 == 0                                           │
│  3. Если True → вычисляем x**2 и добавляем в список                         │
│  4. Результат: [0, 4, 16, 36, 64]                                           │
└─────────────────────────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         NESTED COMPREHENSION                                │
│  matrix = [[1, 2, 3], [4, 5, 6]]                                            │
│  flat = [x for row in matrix for x in row]                                  │
│                                                                             │
│  Аналогично:                                                                │
│  flat = []                                                                  │
│  for row in matrix:   # внешний цикл                                        │
│      for x in row:    # внутренний цикл                                     │
│          flat.append(x)                                                     │
│                                                                             │
│  Результат: [1, 2, 3, 4, 5, 6]                                              │
└─────────────────────────────────────────────────────────────────────────────┘
           │
           ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         СТРУКТУРА SYNTAX                                    │
│                                                                             │
│  [выражение for переменная in итерируемый_объект if условие]                │
│        │          │              │              │                           │
│        │          │              │              └─── фильтр (опционально)   │
│        │          │              └─── источник данных                       │
│        │          └─── текущий элемент                                      │
│        └─── что делаем с элементом                                          │
│                                                                             │
│  Порядок выполнения:                                                        │
│  1. Итерируемся по источнику                                                │
│  2. Проверяем условие (если есть)                                           │
│  3. Вычисляем выражение                                                     │
│  4. Добавляем в новую коллекцию                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Производительность: comprehension vs цикл vs `map`/`filter`

```text
    ┌─────────────────────────────────────────────────────────────┐
    │              ПОЧЕМУ COMPREHENSION БЫСТРЕЕ?                  │
    │                                                             │
    │  ┌───────────────────────────────────────────────────────┐  │
    │  │  ЦИКЛ (Python уровень)                                │  │
    │  │  ┌──────────────────────────────────────────────────┐ │  │
    │  │  │ LOAD_NAME    (result)                            │ │  │
    │  │  │ LOAD_METHOD  (append)   ← поиск метода           │ │  │
    │  │  │ CALL_METHOD  (x * 2)    ← вызов в Python         │ │  │
    │  │  └──────────────────────────────────────────────────┘ │  │
    │  │  ❌ Медленно из-за множества операций                 │  │
    │  └───────────────────────────────────────────────────────┘  │
    │                                                             │
    │  ┌───────────────────────────────────────────────────────┐  │
    │  │  COMPREHENSION (C уровень)                            │  │
    │  │  ┌──────────────────────────────────────────────────┐ │  │
    │  │  │ LIST_APPEND   (оптимизированная C-функция)       │ │  │
    │  │  │ BINARY_OP     (x * 2) в C                        │ │  │
    │  │  └──────────────────────────────────────────────────┘ │  │
    │  │  ✅ Быстро - одна инструкция для append               │  │
    │  └───────────────────────────────────────────────────────┘  │
    │                                                             │
    │  Дополнительно: comprehension использует                    │
    │  специальный байткод LIST_APPEND, который:                  │
    │  - не ищет метод append                                     │
    │  - работает напрямую с внутренним представлением списка     │
    └─────────────────────────────────────────────────────────────┘
```

|Цикл|Comprehension|
|---|---|
|LOAD_ATTR (append)|	LIST_APPEND (специализированный)|
|CALL - вызов в Python|	Нет вызова метода - напрямую в C|
|Медленнее|	Быстрее|

**Практическое правило:** comprehension предпочтителен для простых преобразований в одну строку; если логика требует нескольких условий/веток - читаемость важнее, лучше обычный цикл или именованная функция.

### 4.3 Рекурсивный обход вложенных структур

```text
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                              РЕКУРСИЯ: ОБЩАЯ КОНЦЕПЦИЯ                                      │
│                                                                                             │
│  Рекурсия - вызов функции самой себя                                                        │
└─────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                          СТРУКТУРА РЕКУРСИВНОЙ ФУНКЦИИ                                      │
│                                                                                             │
│                              def recursive_function(параметры):                             │
│                                  # БАЗОВЫЙ СЛУЧАЙ                                           │
│                                  if условие_остановки:                                      │
│                                      return простое_значение                                │
│                                                                                             │
│                                  # РЕКУРСИВНЫЙ ШАГ                                          │
│                                  return recursive_function(уменьшенные_параметры)           │
│                                                                                             │
│  ┌────────────────────────────────────────────────────────────────────────────────────────┐ │
│  │ БАЗОВЫЙ СЛУЧАЙ (Base Case)                                                             │ │
│  │ • Условие, при котором функция перестает вызывать саму себя                            │ │
│  │ • Без него → бесконечная рекурсия → переполнение стека                                 │ │
│  │ • Обычно это минимальные/простые значения: 0, 1, пустой список, пустая строка и т.п.   │ │
│  │ • Пример: if n == 0: return 1                                                          │ │
│  └────────────────────────────────────────────────────────────────────────────────────────┘ │
│                                                                                             │
│  ┌────────────────────────────────────────────────────────────────────────────────────────┐ │
│  │ РЕКУРСИВНЫЙ ШАГ (Recursive Step)                                                       │ │
│  │ • Функция вызывается с изменёнными параметрами                                         │ │
│  │ • Параметры должны приближать к базовому случаю                                        │ │
│  │ • Пример: return n * factorial(n - 1)                                                  │ │
│  └────────────────────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                          ПРИНЦИП РАБОТЫ (СТЕК ВЫЗОВОВ)                                      │
│                                                                                             │
│  Каждый рекурсивный вызов создаёт НОВЫЙ ФРЕЙМ в стеке вызовов (call stack):                 │
│                                                                                             │
│  factorial(3)                                                                               │
│  │                                                                                          │
│  ├── factorial(2)                                                                           │
│  │   │                                                                                      │
│  │   ├── factorial(1)                                                                       │
│  │   │   │                                                                                  │
│  │   │   ├── factorial(0)   ← БАЗА: возвращает 1                                            │  
│  │   │   │                                                                                  │
│  │   │   └── возвращает 1 * 1 = 1                                                           │
```

_Лирическое отступление_

Сложность алгоритма - это оценка того, как быстро растут потребности программы при
увеличении размера входных данных (обозначим его n). Эти потребности бывают двух видов:

• T(n) - Time Complexity (временная сложность): сколько времени (число элементарных
  операций: сложений, сравнений, обращений к памяти) потребуется алгоритму.
  Оценивается в количестве шагов или операций. Зависит от размера входных данных,
  но не от скорости конкретного компьютера.

• S(n) - Space Complexity (пространственная, или ёмкостная, сложность): сколько
  памяти (в байтах) потребуется алгоритму для работы.

Обе сложности выражаются в виде функции от n, например T(n) = 3n² + 2n + 1, и с помощью
асимптотических обозначений (O, Ω, Θ) указывают, к какой "скорости роста" это относится
(например, T(n) = O(n²)).

Время стало главным приоритетом:

• Закон Мура: Память и процессорное время растут экспоненциально, но память за
  последние десятилетия подешевела и стала доступнее в гораздо большей степени,
  чем время обработки.

• Узкое горлышко: Скорость арифметических операций (CPU) росла быстрее, чем скорость
  доступа к данным (чтение/запись в память). Таким образом, "перекачка" данных
  часто является самым медленным этапом, поэтому экономия времени стала критичнее,
  чем экономия места.

Поэтому во многих практических задачах память перестала быть лимитирующим фактором,
и основное внимание уделяется именно T(n) - сколько времени будет выполняться код.

O(log n)

Логарифм в сложности возникает тогда, когда на каждом шаге алгоритм отбрасывает
(или обрабатывает) не n-1 элемент, а половину (или другую постоянную долю) оставшихся
данных.

В рекурсивных алгоритмах это происходит, когда рекурсивная функция вызывает себя
один раз, но с аргументом, уменьшенным в 2 раза (или в несколько раз).

Пример:
def logarithmic_recursion(n):
    if n <= 1:
        return 1
    else:
        return 1 + logarithmic_recursion(n // 2)  # рекурсия на половине!

Рекуррентное соотношение для такого алгоритма: T(n) = T(n/2) + С.

Это означает: чтобы решить задачу размера n, мы делаем один вызов для n/2 и тратим
константное время на сам вызов и проверку.

Разворачивая это соотношение:
• На 1-м уровне: задача n.
• На 2-м уровне: n/2.
• На 3-м уровне: n/4.
...
• На k-м уровне: n / 2^k.

Рекурсия остановится (достигнет базы n=1), когда n / 2^k = 1. Отсюда 2^k = n,
и k = log₂(n).

То есть, чтобы дойти до базы, нам нужно сделать столько рекурсивных вызовов, сколько раз
мы можем разделить n на 2. Количество таких делений и есть логарифм.
