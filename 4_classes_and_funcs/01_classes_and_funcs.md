## Часть 1. Синтаксический сахар (II)

### 1.1 Walrus-оператор `:=` (Python 3.8+)

| Обычное присваивание (`=`) | Walrus-оператор (`:=`) |
|----------------------------|-------------------------|
| **Отдельная строка**<br>`x = 10`<br>`print(x)` | **Присваивание внутри выражения**<br>`(y := 10)   # и присвоили, и значение получили`<br>`print(y)     # y уже существует` |
| **Сначала вычислили, потом проверили**<br>`n = len(data)`<br>`if n > 0:`<br>`    print(n)` | **Вычислили И сохранили в одном месте**<br>`if (n := len(data)) > 0:`<br>`    print(f"Есть {n} элементов")` |
| **В циклах - чтение и проверка**<br>`line = file.readline()`<br>`while line != '':`<br>`    process(line)`<br>`    line = file.readline()` | **Чтение и проверка в заголовке while**<br>`while (line := file.readline()) != '':`<br>`    process(line)`<br>`    # line обновляется автомагически` |
| **Не работает внутри**<br>• f-строк<br>• comprehensions (кроме условия) | **Везде, где ждут выражение**<br>`[res for x in data if (res := func(x)) > 0]` |
| Разделение вычисления<br>и использования | Слияние вычисления<br>и использования |

**Когда полезно:** циклы `while`, list comprehension с промежуточным вычислением, чтобы не вызывать функцию дважды.

### 1.2 Тернарный оператор

Синтаксис:
значение_если_да if условие else значение_если_нет

Присваивание в одну строку, заменяет if-else из двух веток.
Цепочка условий в одной строке, заменяет if-elif-else.

**Вложенные выражения рекомендуется использовать осторожно - читаемость резко падает.**

### 1.3 Распаковка (unpacking)

Множественное присваивание:

1. Параллельное присваивание:
   Слева - кортеж переменных, справа - итерируемый объект.
   Количество должно совпадать.

2. Расширенная распаковка с астериском (*):
   *захватывает произвольное количество элементов в список.
   Может стоять в начале, середине или конце:
   - first, *rest = iterable       - первый + всё остальное списком
   - *init, last = iterable        - всё кроме последнего списком + последний
   - first, *middle, last = iterable - первый, середина списком, последний

3. Распаковка в вызовах функций:
   func(*args) - звёздочка разворачивает итерируемый объект в позиционные аргументы.

4. Слияние словарей через **:
   {**dict1, **dict2} - создаёт новый словарь, объединяя ключи.
   Если ключи повторяются, побеждает последний (правый).
   Удобно для создания копии с изменёнными полями.

### 1.4 `*args` и `**kwargs`

**Как это работает:**

1. **`*args`** (с одним астериском) - собирает все переданные позиционные аргументы в **кортеж** `args`.

2. **`**kwargs`** (с двумя астерисками) - собирает все переданные именованные аргументы в **словарь** `kwargs`.

**Имена `args` и `kwargs` - соглашение.** Синтаксически важны только астериски: можно писать `*items`, `**config` и т.д., но `args` и `kwargs` - общепринятый стандарт.

**Внутри функции:**
- `args` - это обычный кортеж, можно итерировать, обращаться по индексу.
- `kwargs` - это обычный словарь, можно использовать `.get()`, `.items()` и т.д.

Используется повсеместно в декораторах, обёртках API, ORM-моделях - везде, где нужно прокинуть произвольные аргументы дальше.

### 1.5 `zip` и `enumerate`

**`zip`** - объединяет несколько итерируемых объектов поэлементно в кортежи.

**`enumerate`** - оборачивает итерируемый объект и выдаёт пары (индекс, элемент).
Индекс по умолчанию с нуля, параметр `start` сдвигает начало отсчёта.

**Совместное использование `enumerate(zip(...))`:**

- `zip(names, scores)` даёт пары: `("Аня", 85)`, `("Борис", 92)`, `("Вера", 78)`
- `enumerate(..., start=1)` добавляет нумерацию с единицы: `(1, ("Аня", 85))`, ...


**`zip(*matrix)` для транспонирования:**

- `*matrix` распаковывает матрицу - строки становятся отдельными аргументами: `zip([1,2,3], [4,5,6])`
- `zip` берёт элементы с одинаковыми индексами: первые элементы строк `(1,4)`, вторые `(2,5)`, третьи `(3,6)`
- Строки превращаются в столбцы - готовая транспонированная матрица.

matrix = [[1, 2, 3], [4, 5, 6]]

list(zip(matrix))
→ [([1, 2, 3],), ([4, 5, 6],)]
  zip получает 1 аргумент - список matrix целиком.
  Каждый элемент matrix (то есть целая строка) упаковывается в кортеж из одного элемента.

list(zip(*matrix))
→ [(1, 4), (2, 5), (3, 6)]
  *matrix распаковывает matrix в 2 отдельных аргумента: [1,2,3] и [4,5,6].
  zip получает 2 аргумента и объединяет их поэлементно:
  первые элементы → (1, 4), вторые → (2, 5), третьи → (3, 6).

### 1.6 Продвинутые f-strings

_Базовые операторы форматирования в f-строках:_

{var} - вставка значения переменной.
{var=} - отладочный вывод с именем переменной (Python 3.8+).
{var:spec} - форматирование, где spec это: .2f (число с плавающей точкой, два знака после запятой), .2e (экспоненциальная форма), , (разделитель тысяч запятой), >10 (выравнивание по правому, ширина 10), <10 (по левому), ^10 (по центру). Можно комбинировать: {value:>10,.2f} - ширина 10, запятые, два знака после запятой, выравнивание вправо.

### 1.7 Декораторы

Декоратор - это функция, которая принимает одну функцию и возвращает другую, добавляя поведение до/после вызова.

_Простой декоратор:_

def timer(func):                  # 1. Принимает функцию, которую декорируем
    @functools.wraps(func)        # 2. Копирует метаданные (имя, докстринг) (опционально, больше нужно для разработчиков ПО на python)
    def wrapper(*args, **kwargs): # 3. Обёртка с любыми аргументами
        # ... код до вызова ...
        result = func(*args, **kwargs)  # 4. Вызов оригинальной функции
        # ... код после вызова ...
        return result             # 5. Возвращает результат оригинальной функции
    return wrapper                # 6. Возвращает обёртку вместо оригинальной функции

@timer                            # синтаксический сахар
def slow_sum(n): ...              # эквивалентно: slow_sum = timer(slow_sum)

Что делает @functools.wraps:
- Копирует __name__, __doc__, __module__ из func в wrapper
- Без него slow_sum.__name__ покажет "wrapper" вместо "slow_sum"

_Декоратор с параметрами:_

def retry(times=3):               # 1. Внешняя функция - принимает параметры декоратора
    def decorator(func):          # 2. Средняя функция - сам декоратор
        @functools.wraps(func)
        def wrapper(*args, **kwargs): # 3. Обёртка с логикой
            # использует times из замыкания
        return wrapper
    return decorator              # 4. Возвращает декоратор

@retry(times=5)                   # Сначала retry(times=5) вызывается,
def fetch(): ...                  # возвращает decorator,
                                  # потом decorator(fetch) заменяет функцию.
                                  # Эквивалентно: fetch = retry(times=5)(fetch)

Ключевое различие:
- @decorator       - decorator - это сам декоратор (принимает функцию)
- @decorator(...)  - decorator(...) вызывается и возвращает декоратор (принимает функцию)

## Часть 2 - Типизация

Python - язык с динамической типизацией, но модуль `typing` даёт статические подсказки типов, которые проверяются внешними инструментами (сам интерпретатор это никак не проверяет).

> В Python 3.9+ можно писать `list[int]`, `dict[str, int]` напрямую, без импорта `List`/`Dict` из `typing`.

### 2.2 `Optional`, `Union` и `|`

В Python `Optional[X]` - это просто сокращение для `Union[X, None]`, которое означает "либо значение типа X, либо None".
Используется, когда функция может не найти результат (например, поиск пользователя вернул пустой ответ). 

`Union[A, B]` - общий механизм для указания "значение может быть типа A или типа B" (допустим, параметр принимает и строки, и числа). 

Начиная с Python 3.10, появился оператор `|` как более короткая альтернатива: `X | Y` эквивалентно `Union[X, Y]`, а `X | None` эквивалентно `Optional[X]`, и импорт из модуля `typing` для этого больше не нужен. 

_Совет_: Пользуйтесь `|`

### 2.3 `Literal`

`Literal` - конструкт для конкретных значений. 

`Literal["train", "eval", "predict"]`: "параметр обязан быть одной из этих трёх конкретных строк, и ничем другим". 

Если попытаться передать `"debug"`, статический анализатор (mypy, pyright) сразу подсветит ошибку, хотя сам Python этого не запрещает.

### 2.4 `@dataclass` - замена "словарей с данными"

Частая ошибка в аналитическом коде - таскать данные в "голых" словарях (`{"name": ..., "value": ...}`), где легко опечататься в ключе и получить `KeyError` в рантайме. `dataclass` решает это через явную структуру.

Декоратор `@dataclass` автоматически генерирует конструктор, красивое текстовое представление и сравнение по значениям - всё то, что для обычного класса пришлось бы писать вручную.
В результате код становится безопаснее: IDE подсвечивает опечатки в именах полей ещё до запуска, а обращение через точку вместо квадратных скобок делает чтение и поддержку кода проще. 
Датаклассы идеально подходят для моделей данных, DTO и любых сущностей с чёткой структурой, в то время как словари лучше оставить для динамических или одноразовых сценариев.

### 2.5 Базовые `Protocol` и `Generic`

`Protocol` и `Generic` - это два инструмента для продвинутой типизации. 
`Protocol` определяет структурный подтип: объект считается совместимым с протоколом, если у него есть все нужные методы и атрибуты, даже если он явно не наследует этот протокол. Это позволяет реализовать так называемую "утиную типизацию" с проверкой типов - если объект крякает как утка, этот объект утка. 

`Generic` же позволяет создавать контейнеры и классы, параметризованные типом: например, список чисел - это List[int], а результат функции может быть Optional[str]. Это делает код более гибким и переиспользуемым, сохраняя при этом строгую проверку типов - компилятор знает, что именно вы храните или возвращаете.

### 2.6 Зачем `mypy` в команде

- Типы - это **исполняемая документация**: не нужно лезть в реализацию функции, чтобы понять, что она принимает и возвращает.
- Статический анализатор (`mypy`, `pyright`) ловит ошибки типов **до** запуска кода - особенно ценно в пайплайнах данных, где ошибка вылезает через час обработки.
- Упрощает ревью кода и рефакторинг больших кодовых баз.
- **Важно проговорить:** аннотации типов в Python - это подсказки, интерпретатор их не проверяет. Проверка - задача отдельного инструмента (`mypy`), который обычно встраивают в CI.

## Часть 3. Парадигмы программирования

### 3.1 Процедурный стиль

Процедурный стиль, представляет собой подход, где данные и функции, оперирующие этими данными, существуют раздельно. 

Функции принимают структуры данных в качестве аргументов и модифицируют их, но сами не имеют собственного состояния. 

Это порождает фундаментальную архитектурную проблему: бизнес-правила становятся жестко привязанными к конкретному представлению данных. Любое изменение структуры данных - добавление поля, изменение типа, рефакторинг формата хранения - приводит к необходимости переписывать все функции, которые с этими данными работают. Таким образом, высокоуровневая политика (бизнес-логика) оказывается зависимой от низкоуровневых деталей реализации. В терминах "Чистой архитектуры", это нарушает принцип независимости от внешних факторов, делая систему хрупкой и трудноизменяемой.

### 3.2 Функциональный стиль

Функциональное программирование, предлагает решение некоторых проблем процедурного подхода за счет принудительной неизменяемости данных и чистоты функций. 

Здесь данные не изменяются, а преобразуются через цепочки функций, каждая из которых возвращает новый результат. 

Это снижает количество побочных эффектов и делает код более предсказуемым и тестируемым. Однако функциональный стиль не решает основной архитектурной проблемы - зависимость от конкретных структур данных сохраняется. Функции по-прежнему оперируют конкретными типами записей, и изменение структуры требует изменений во всей цепочке преобразований. Функциональные языки хорошо подходят для определенных слоев архитектуры (например, для бизнес-логики с интенсивными вычислениями), но не заменяют объектно-ориентированный подход в создании гибких архитектурных границ между компонентами.

_Lambda_

Лямбда-выражение (или анонимная функция) - это небольшая функция, которая определяется без имени с помощью ключевого слова `lambda`. 
Она может принимать любое количество аргументов, но может содержать только одно выражение, которое автоматически возвращается.

```python
# Примеры:
lambda x: x * 2                    # один аргумент
lambda x, y: x + y                 # два аргумента
lambda x, y, z: x * y + z          # несколько аргументов
lambda x, y=10: x + y              # с значениями по умолчанию
lambda *args: sum(args)            # с *args
lambda x, *args, y=1: x + y        # комбинированный синтаксис
```

_Генераторы в Python_

Генераторы - функции, которые используют `yield` для возврата последовательности значений по одному, сохраняя состояние между вызовами. 
Принцип - `lazy computations` значения вычисляются только при запросе.

Значения вычисляются только в момент их фактической необходимости, а не заранее.

### 3.3 Объектно-ориентированный стиль

Объектно-ориентированный стиль, принципиально отличается от двух предыдущих подходов. 

В ООП данные и поведение инкапсулированы внутри объектов, но главное - использование полиморфизма и интерфейсов позволяет создавать абстрактные границы между компонентами.

Высокоуровневые модули (бизнес-правила) взаимодействуют не с конкретными реализациями, а с абстракциями (интерфейсами), что делает их независимыми от деталей - баз данных, UI, внешних API. Это реализует принцип Dependency Inversion и делает архитектуру "подключаемой". В правильно спроектированной ОО-системе можно заменить способ хранения данных, протокол обмена или пользовательский интерфейс без изменения бизнес-логики.

### 3.4 ООП: наследование vs композиция

### Наследование (is-a)

Наследование создаёт жёсткую связь между родительским и дочерним классами. 

Дочерний класс полностью зависит от реализации родителя, что нарушает принцип открытости/закрытости.

Любое изменение в базовом классе может непредсказуемо повлиять на всех потомков. Иерархии наследования быстро становятся хрупкими при росте требований - добавление новой функциональности требует изменения всей цепочки, а множественное наследование порождает ромбовидные проблемы. В терминах "Чистой архитектуры", наследование создаёт зависимость от конкретной реализации, а не от абстракции, что делает систему трудноизменяемой и усложняет тестирование изолированных компонентов.

### Композиция (has-a)

Композиция предлагает альтернативный подход, где объекты собираются из независимых компонентов через интерфейсы. 

Класс не расширяет функциональность через наследование, а получает готовые компоненты через конструктор, методы или внешние зависимости. Это реализует принцип Dependency Inversion - высокоуровневый модуль зависит от абстракции, а не от конкретной реализации. Композиция позволяет подменять поведение во время выполнения, упрощает тестирование через моки и делает систему гибкой к изменениям. В правильно спроектированной архитектуре компоненты легко заменяются, расширяются и переиспользуются без изменения существующего кода.

### Почему композиция предпочтительнее

Наследование нарушает принцип единственной ответственности и создаёт нежелательные связи между уровнями абстракции. Композиция, напротив, позволяет строить системы из слабосвязанных модулей, где каждый компонент отвечает за свою область. Это соответствует главному правилу архитектуры: зависимости должны направляться внутрь, от внешних деталей к внутренним бизнес-правилам. Композиция даёт возможность легко изменять поведение системы без переписывания иерархий, делает код более тестируемым и поддерживаемым. 

Поэтому в современной архитектуре предпочтение всегда отдаётся композиции перед наследованием.

_Лирическое отсутпление_:
В Python нижнее подчёркивание в начале имени атрибута (например, `_totals`, `_aggregator`) - это соглашение, которое сигнализирует о том, что данный атрибут предназначен для внутреннего использования внутри класса или модуля. Он не является частью публичного интерфейса и не должен использоваться за пределами класса.

### 3.5 Dunder-методы

_Магические методы_

Dunder-методы (от double underscore) - это специальные методы в Python, которые определяют поведение объектов встроенным операторам и функциям. Они позволяют классам интегрироваться с синтаксисом языка, делая объекты более "естественными" в использовании - как встроенные типы.

1. **Инициализация и представление.** `__init__` управляет созданием объекта, `__repr__` и `__str__` определяют строковые представления для отладки и пользователей. Это базовая точка входа в объект.

2. **Операторы сравнения.** `__eq__`, `__lt__`, `__le__` и другие позволяют объектам участвовать в сравнениях.

3. **Арифметические операции.** `__add__`, `__sub__`, `__mul__` и аналогичные перегружают математические операторы. Здесь особенно критична валидация - метод `__add__` проверяет валюты перед сложением, предотвращая некорректные операции на уровне бизнес-правил.

Dunder-методы - это мост между предметной областью и синтаксисом языка. Они позволяют создавать выразительный код, который читается как бизнес-правила. Например, `a + b` интуитивно понятно для операций с деньгами, в отличие от вызова `a.add(b)`. Это сильно снижает когнитивную нагрузку кода.

#### Важные принципы

- **Единообразие.** Объекты должны вести себя предсказуемо - если определено сложение, оно должно быть коммутативным и ассоциативным, как и для чисел.
- **Безопасность.** Проверки вроде `isinstance(other, Money)` и `NotImplemented` защищают от неверных типов, сохраняя целостность системы.
- **Согласованность.** `__eq__` и `__hash__` должны быть согласованы - если объекты равны, их хеши тоже должны совпадать.

#### Когда использовать

Dunder-методы следует определять, когда объекты моделируют сущности с естественными операциями - деньги, даты, координаты, точки. Избыточное использование (например, перегрузка `__add__` для пользователей или заказов) может запутывать. Главное правило: операторы должны быть интуитивно понятны и соответствовать ожиданиям предметной области.

### 3.6 Метаклассы: как Python создаёт сами классы

_Метаклассы_

Метаклассы отвечают на вопрос: а кто создаёт сам объект class? 

Ключевой факт: в Python классы - это тоже объекты, и у них тоже есть тип. `type` - это метакласс по умолчанию, который создаёт все классы, объявляемые через ключевое слово `class`. 
`type` можно вызвать напрямую без использования `class`, из чего следует, что классы - это просто объекты, создаваемые вызовом `type` с тремя аргументами: именем класса, кортежем родительских классов и словарём атрибутов.

Собственный метакласс создаётся путём наследования от `type` и переопределяет процесс создания классов. Внутри метакласса метод `__new__` получает управление в момент объявления класса - ещё до того, как создан хотя бы один экземпляр. Это позволяет перехватывать, модифицировать или расширять поведение на этапе определения класса.

#### Практическое применение

**Автоматическая регистрация подклассов.** Это реализует паттерн "плагины", где все дочерние классы автоматически добавляются в реестр. Базовый класс выступает как точка расширения - новые реализации просто объявляются и сразу становятся доступными системе без необходимости явно их регистрировать. Это соответствует принципу открытости/закрытости.

```text

│                   Конфигурация (центральная)                    │

                            │ управляет
```

**Валидация структуры класса.** Метакласс может проверять, что класс содержит необходимые методы или атрибуты, ещё до того, как будут созданы его экземпляры. В ORM-библиотеках это позволяет гарантировать, что каждая модель описывает поля, а в Pydantic - что определена схема валидации.

**Синглтон на уровне метакласса.** Переопределяя `__call__`, метакласс контролирует, как создаются экземпляры класса. Это позволяет гарантировать, что для класса будет существовать только один экземпляр. В отличие от реализации синглтона внутри самого класса, метакласс решает задачу чисто и прозрачно.

#### Архитектурное значение

В терминах "Чистой архитектуры", метаклассы находятся на самом низком уровне - это инфраструктурный инструмент, который управляет созданием и структурой самих объектов предметной области. Они позволяют вводить контракты и инварианты на уровне языка, делая код более самопроверяемым и уменьшая количество шаблонного кода. Однако метаклассы следует использовать умеренно - они усложняют понимание кода и должны применяться только там, где требуется управление на уровне классов, а не экземпляров. Это мощный, но тяжёлый инструмент, которым не стоит злоупотреблять в повседневном коде.

_Лирическое отступление_:
Метаклассы - мощный, но редко необходимый инструмент. 
*"Metaclasses are deeper magic than 99% of users should ever worry about"*.
Можете надуть щеки на собеседовании продемонстрировав знания метаклассов в python

|---|---|---|

## Часть 4. Исключения и контекстные менеджеры

### 4.1 try / except / else / finally

Конструкция `try/except/else/finally` в Python предоставляет механизм обработки исключений и управления ресурсами. Это фундаментальный инструмент для написания надёжного кода, который корректно обрабатывает ошибки и гарантирует освобождение ресурсов.

#### Структура

**try** - блок, содержащий код, который может вызвать исключение. Интерпретатор пытается выполнить код в этом блоке.

**except** - перехватывает и обрабатывает исключения определённого типа. Может быть несколько блоков `except` для разных типов исключений. Если исключение не перехвачено, оно всплывает выше по стеку вызовов.

**else** - выполняется, только если в блоке `try` не возникло ни одного исключения. Позволяет отделить основной код от кода, который должен выполняться только при успешном завершении.

**finally** - выполняется всегда, независимо от того, возникло исключение или нет. Используется для освобождения ресурсов (закрытие файлов, соединений, снятие блокировок). Даже если в `except` есть `return` или `raise`, `finally` выполнится до того, как управление покинет функцию.

#### Порядок выполнения

1. Выполняется блок `try`.
2. Если исключений нет → выполняется `else` (если есть), затем `finally`.
3. Если исключение возникло → выполняется соответствующий `except`, затем `finally`.
4. Если в `except` есть `return` или `raise`, `finally` выполнится перед выходом из функции.

#### Когда использовать

**else** - когда есть код, который должен выполниться только при успешном выполнении `try`, но при этом его не нужно помещать в `try` (чтобы он не перехватывал свои собственные исключения). Это улучшает читаемость и разделяет ответственность.

**finally** - всегда для очистки ресурсов. Закрытие файлов, соединений с БД, снятие блокировок, освобождение памяти, логирование факта завершения операции.

#### Правила чистого кода

- Перехватывайте только те исключения, которые вы можете обработать.
- Никогда не используйте голый `except:` - это скрывает все ошибки, включая системные.
- Используйте `else` для успешного сценария, чтобы уменьшить вложенность.
- Используйте `finally` только для освобождения ресурсов, не для бизнес-логики.
- Пропускайте исключения, которые не можете обработать (используйте `raise`).
- Логируйте ошибки с достаточным контекстом.
- Не используйте обработку исключений для управления потоком выполнения.
- В конструкторах и деструкторах избегайте сложной логики с исключениями.
- Для ресурсозависимых операций используйте контекстные менеджеры (`with`), они реализуют ту же логику `try/finally` автоматически.

### 4.2 Кастомные исключения

Кастомные исключения - классы, унаследованные от `Exception`, для иерархии ошибок предметной области.

**Зачем:** группировка ошибок, передача контекста через атрибуты.

**Правила:** наследовать от `Exception`, суффикс `Error`, передавать сообщение в `super().__init__()`.

Собственная иерархия исключений позволяет вызывающему коду ловить как конкретную ошибку, так и целую категорию (`except DataValidationError`).

### 4.3 `with` и протокол контекстного менеджера

`with` управляет ресурсами, гарантируя их освобождение при выходе из блока. Контекстный менеджер реализует методы `__enter__` (вход) и `__exit__` (выход). `__exit__` вызывается всегда, даже при исключении. Это заменяет `try/finally`.

### 4.4 Собственный контекстный менеджер через класс

Класс реализует `__enter__` и `__exit__`. `__enter__` возвращает объект для использования в блоке. `__exit__` получает информацию об исключении и может подавить его (вернуть `True`).

### 4.5 Через `contextlib.contextmanager`

Декоратор превращает функцию-генератор в контекстный менеджер. Код до `yield` - вход, код после - выход. `yield` - точка выполнения блока `with`. Конструкция с `try/finally` внутри гарантирует очистку.
