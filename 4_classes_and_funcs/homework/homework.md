## Упражнение 1. Walrus-оператор

Дан список строк (потенциально «грязных» логов):

```python
logs = ["error: 12", "ok", "error: 45", "info", "error: 7", "warn"]
```

Используя **walrus-оператор** внутри list comprehension, извлеките числовые коды из строк вида `"error: N"` (то есть примените функцию разбора один раз, а не дважды) и соберите список только тех кодов, которые больше 10. Строки без `"error:"` игнорируйте.

Напишите функцию `parse_error_code(s: str) -> int | None`, которая возвращает код ошибки или `None`, и используйте её в comprehension вместе с `:=`.

## Упражнение 2. Тернарный оператор

Напишите функцию `classify_score(score: int) -> str`, которая одной строкой (цепочка тернарных операторов) возвращает:

- `"B"` при `75 <= score < 90`

Затем объясните в комментарии, почему вложенные тернарные операторы стоит использовать с осторожностью.

## Упражнение 9. Парадигмы: процедурный vs функциональный vs ООП

Дан список заказов:

```python
orders = [
    {"customer": "Аня", "amount": 1200},
    {"customer": "Борис", "amount": 450},
    {"customer": "Аня", "amount": 300},
    {"customer": "Вера", "amount": 900},
]
```

Реализуйте подсчёт суммарной выручки по каждому клиенту тремя способами:
1. **Процедурный стиль** — обычный цикл `for` с накоплением в словаре.
2. **Функциональный стиль** — через `functools.reduce` или `collections.defaultdict` с comprehension.
3. **ООП стиль** — класс `RevenueAggregator` с методами `add(order: dict)` и `as_dict() -> dict`, инкапсулирующий состояние.

В комментарии кратко опишите, какой вариант проще расширить, если появится требование учитывать ещё и валюту заказа.
