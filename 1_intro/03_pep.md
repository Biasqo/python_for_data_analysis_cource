# PEP и PEP 8

## Что такое PEP?
**PEP** (Python Enhancement Proposal) - документ с предложениями по развитию Python.  
**PEP 8** - руководство по стилю кода, чтобы он был читаемым и единообразным.

_Как разработчик уверяю вас - код читают 90% времени, пишут 10% - поэтому читаемость кода жизненно важна!_

## Основные правила PEP 8

| Раздел | Правило |
|--------|---------|
| **Отступы** | 4 пробела на уровень. Запрещены табуляции. |
| **Длина строки** | Код - ≤ 79 символов; комментарии и docstrings - ≤ 72. |
| **Пустые строки** | 2 строки между функциями/классами верхнего уровня, 1 между методами класса. |
| **Импорты** | Каждый на отдельной строке, в начале файла. Группировка: стандартные → сторонние → свои. |
| **Пробелы** | Вокруг бинарных операторов (`=`, `+`, `==`, `and` и др.). После запятых, но не внутри скобок: `spam(ham[1])`. |
| **Именование** | Переменные/функции: `snake_case` <br> Классы: `CamelCase` <br> Константы: `UPPER_CASE` <br> «Приватные»: `_leading_underscore` |
| **Комментарии** | Блоковые - с `# ` и пробелом, на том же уровне отступа. inline - отделены от кода двумя пробелами. |
| **Сравнения** | С `None` - только `is`/`is not`. Не пишите `if x is None` как `if x == None`. |
| **Проверка пустоты** | Для последовательностей: `if not seq:` вместо `if len(seq) == 0`. |
| **Строки** | Для проверки префиксов/суффиксов используйте `.startswith()`/`.endswith()`, а не срезы. |
| **Булевы значения** | Не сравнивайте с `True`/`False` через `==` - пишите `if greeting:`. |
| **Имена-табу** | Никогда не используйте `l`, `O`, `I` как имена переменных - путают с `1` и `0`. |

## Чего избегать?
- `from module import *` (засоряет пространство имён).
- Смешивания табуляций и пробелов.
- Лишних пробелов: внутри скобок, перед скобкой вызова, перед запятыми/двоеточиями.
- Длинных строк без переноса (используйте скобки для переноса).
- Составных операторов на одной строке (`if x: do()` - только для очень коротких тел, но лучше избегать).

## Как проверить свой код?
- **Линтеры** автоматически проверяют стиль: `flake8`, `pylint`.
- **Автоформатирование**: `black` приводит код к PEP 8.

### Выявление
- Через плагин `flake8` либо же через библиотеку `flake8`
`flake8 my_fyle.py`

### Исправление
- Установите библиотеку `autopep8`
`autopep8 --in-place my_file.py`

## Помните
Правила PEP 8 - это **рекомендации**, а не жёсткие законы. Если правило делает код менее читаемым или ломает совместимость - отступите от него. Главное - **единообразие внутри проекта**.
