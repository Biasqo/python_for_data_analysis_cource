## Проверка понимания

**5 вопросов (минута 83):**

1. Почему GIL не позволяет потокам ускорять CPU-ограниченные задачи?
   > GIL гарантирует, что в один момент времени только один поток выполняет байткод Python. Несколько потоков не могут выполнять код параллельно — они чередуются. При чистых вычислениях это не даёт никакого ускорения.

2. Чем `await asyncio.sleep(1)` отличается от `time.sleep(1)`?
   > `asyncio.sleep` приостанавливает корутину и освобождает цикл событий для выполнения других корутин. `time.sleep` блокирует весь поток, не позволяя выполняться никакому конкурентному коду.

3. Почему код с многопроцессорностью должен находиться внутри `if __name__ == "__main__"`?
   > В Windows/macOS новые процессы создаются путём импорта модуля. Без этой защиты каждый дочерний процесс порождал бы новые дочерние, вызывая бесконечную рекурсию.

4. Вам нужно выполнить 200 запросов к REST API. Какой инструмент и почему?
   > `asyncio` с `aiohttp` — это I/O-ограниченная задача. Async эффективно обрабатывает множество конкурентных запросов без накладных расходов на несколько процессов.

5. `Pool.map` сериализует аргументы через pickle. Когда эти накладные расходы делают многопроцессорность нецелесообразной?
   > Когда каждая отдельная задача завершается быстрее, чем занимает сериализация туда-обратно (миллисекунды для больших данных). Небольшие быстрые задачи нередко выполняются быстрее последовательно.
