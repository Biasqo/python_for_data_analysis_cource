# Как работает CPython: краткий обзор

## Что такое CPython?

**CPython** - эталонная реализация языка Python, написанная на C. Именно её вы скачиваете с python.org. Она компилирует ваш Python-код в байт-код, который затем выполняется виртуальной машиной.

## Основные этапы работы CPython

### 1. Лексический анализ (Tokenizer)

Исходный код разбивается на **токены** - минимальные смысловые единицы (ключевые слова, операторы, идентификаторы, строки, числа и т.д.).

```python
# Исходный код
x = 42

# Токены:
# NAME 'x', OP '=', NUMBER '42'
```

### 2. Синтаксический анализ (Parser)

Из токенов строится **AST** (Abstract Syntax Tree - абстрактное синтаксическое дерево). Оно представляет структуру программы в виде дерева, где узлы - это операторы, выражения, функции и т.д.

С версии Python 3.9 CPython использует **PEG-парсер** (Parsing Expression Grammar), который заменил старый LL(1)-парсер. PEG-парсер более гибкий и позволяет описывать более сложные грамматические конструкции без обходных путей.

```python
# AST для x = 42
Assignment(
    target=Name(id='x'),
    value=Constant(value=42)
)
```

### 3. Компиляция в байт-код

AST преобразуется в **байт-код** - низкоуровневые инструкции для виртуальной машины Python (CEVAL).

```python
# Байт-код для x = 42
LOAD_CONST 42
STORE_NAME x
```

### 4. Исполнение байт-кода (CEVAL)

Виртуальная машина CPython (цикл CEVAL) выполняет байт-код инструкция за инструкцией. Это стековая виртуальная машина - инструкции оперируют стеком данных.

- `LOAD_CONST` - кладёт значение на стек.
- `STORE_NAME` - забирает значение со стека и сохраняет в переменную.

Начиная с Python 3.11, CEVAL использует **специализирующий адаптивный интерпретатор** (PEP 659). Часто выполняемые инструкции могут "переписывать" себя в более быстрые специализированные версии во время выполнения - например, `LOAD_ATTR` может стать `LOAD_ATTR_INSTANCE_VALUE`, если интерпретатор замечает, что тип объекта не меняется. Это заметно ускоряет исполнение без изменения семантики байт-кода.

## Ключевые компоненты CPython

| Компонент | Назначение |
|---|---|
| **PyObject** | Базовый тип для всех объектов в Python. Все объекты (`int`, `str`, `list` и т.д.) - структуры C, наследующие от `PyObject`. |
| **PyTypeObject** | Описывает тип объекта: методы, атрибуты, размер в памяти. |
| **Interpreter State** | Глобальное состояние интерпретатора: загруженные модули, настройки. |
| **Thread State** | Состояние каждого потока: текущий кадр стека, обработчики исключений. |
| **Frame** | Кадр стека - представляет один вызов функции. Содержит локальные переменные, байт-код, указатель на следующий кадр. |
| **GIL** (Global Interpreter Lock) | Блокировка, которая позволяет выполнять байт-код только одному потоку одновременно. Упрощает управление памятью, но ограничивает параллелизм. |

> **Важно про GIL:** начиная с Python 3.13 (PEP 703) появилась экспериментальная **free-threaded сборка** CPython, которая может работать без GIL. Пока это экспериментальная опция, а не поведение по умолчанию, но в будущих версиях ситуация может измениться.

## Управление памятью

### 1. Сборщик мусора (GC)

CPython использует **подсчёт ссылок** + **циклический сборщик мусора**:

- **Подсчёт ссылок** - каждый объект хранит счётчик ссылок на себя. Когда счётчик становится 0, объект удаляется.
- **Циклический сборщик** - обнаруживает и удаляет объекты, которые ссылаются друг на друга (циклы), которые подсчёт ссылок сам по себе не может освободить.

### 2. Аллокатор памяти (pymalloc)

CPython имеет свой менеджер памяти для маленьких объектов (до 512 байт) - это ускоряет создание и удаление объектов, избегая накладных расходов на системные вызовы `malloc`/`free`.

## Схема работы CPython

```
┌─────────────┐
│  .py файл   │
└──────┬──────┘
       ▼
┌─────────────┐
│  Tokenizer  │ → Токены
└──────┬──────┘
       ▼
┌─────────────┐
│   Parser    │ → AST (PEG-парсер, с 3.9)
└──────┬──────┘
       ▼
┌─────────────┐
│  Compiler   │ → Байт-код (.pyc для модулей)
└──────┬──────┘
       ▼
┌─────────────┐
│   CEVAL     │ → Исполнение (адаптивная стековая ВМ, с 3.11)
└──────┬──────┘
       ▼
┌─────────────┐
│  Результат  │
└─────────────┘
```

## Итоги по версиям Python

| Версия | Изменение |
|---|---|
| 3.9 | Новый PEG-парсер вместо LL(1) |
| 3.11 | Специализирующий адаптивный интерпретатор (PEP 659), значительный прирост скорости |
| 3.13 | Экспериментальная free-threaded сборка без GIL (PEP 703) |
