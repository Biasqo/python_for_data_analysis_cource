## Домашнее задание 2 — Виртуальное окружение: virtualenv, conda

1. Создайте репозиторий проекта с виртуальным окружением (venv **или** conda — на выбор) и зависимостями `numpy`, `pandas`. Включите файл окружения (`requirements.txt` или `environment.yml`), `.gitignore` и `README.md` с инструкцией по установке с нуля.
2. Письменно (полстраницы): сравните venv и conda для команды, которой нужны (а) воспроизводимая установка на разных ОС, (б) нативная зависимость (например, библиотека для PySpark или CUDA), (в) быстрый онбординг новых сотрудников. Дайте обоснованную рекомендацию.
3. Создайте `.env`-файл с тестовыми переменными (например, `API_KEY`, `DATA_PATH`) и напишите скрипт, который читает их через `python-dotenv` и завершает работу с понятной ошибкой, если переменная не задана.
4. Напишите скрипт `env_report.py`, который выводит версию Python, путь к интерпретатору, список установленных пакетов с версиями (через `importlib.metadata` или `pip freeze`) — и сохраняет это в файл `environment_report.txt`. Объясните, зачем такой отчёт может быть полезен при отладке "у меня работает, а у тебя нет".
5. Письменно (короткий ответ): в чём разница между `pip freeze > requirements.txt` и явным описанием зависимостей в `pyproject.toml` (например, через poetry/uv)? Почему `pip freeze` считается "снимком", а не источником истины?
