# Блок 5. Асинхронность и параллелизм

## Занятие 5. AsyncIO и Multiprocessing

**Цель:** понимать разницу между конкурентностью и параллелизмом, GIL и его последствия, и уметь выбрать правильный инструмент (asyncio / threading / multiprocessing) для задачи анализа данных.

| Время | Тема | Детали |
|---|---|---|
| 0–15 | Concurrency vs parallelism, GIL | Что такое Global Interpreter Lock, почему потоки в Python не ускоряют CPU-bound код, но помогают при I/O-bound. |
| 15–45 | AsyncIO | Event loop, `async`/`await`, корутины, `asyncio.gather`, асинхронные контекстные менеджеры (`async with`), типичный сценарий — параллельные запросы к API/скачивание файлов. |
| 45–70 | Multiprocessing | `Process`, `Pool`, `Pool.map`/`imap`, передача данных между процессами, накладные расходы на сериализацию (pickle), когда оверхед не стоит выигрыша. |
| 70–85 | Выбор инструмента | Дерево решений: I/O-bound → asyncio/threading; CPU-bound → multiprocessing; типичные задачи анализа данных (параллельная обработка файлов, батч-вызовы API, параллельный препроцессинг для ML). |
| 85–90 | Введение в домашнее задание | Постановка задачи. |

**Демонстрация:** показываем три версии одной задачи — "скачать 50 файлов по URL и посчитать статистику по каждому": синхронно, через `asyncio` (I/O-bound выигрыш) и через `multiprocessing.Pool` для CPU-bound части (парсинг/вычисления) — сравниваем время выполнения.

# Блок 8. Оркестрация

## Занятие 13. ETL и оркестрация

**Цель:** собрать всё пройденное в единый управляемый pipeline и понять базовые принципы оркестрации, без которых аналитический код остаётся "разовым скриптом".

| Время | Тема | Детали |
|---|---|---|
| 0–15 | Что такое ETL | Extract / Transform / Load, batch vs streaming (обзорно), где в этой схеме pandas/polars/pyspark из блока 6. |
| 15–35 | Принципы надёжных pipeline | Идемпотентность, логирование, обработка ошибок и повторные попытки (retry), разделение на атомарные шаги, инкрементальная загрузка. |
| 35–65 | Инструменты оркестрации | Концепции DAG (направленный ациклический граф задач), зависимости между задачами, расписания (cron-подобные). Обзор Airflow, Prefect, Dagster — назначение, отличия, когда какой выбрать; практика на более лёгком инструменте (например, Prefect) с простым flow из 2–3 задач. |
| 65–85 | Сборка итогового pipeline | Объединяем шаги предыдущих занятий (extract из CSV/API → transform на pandas/polars → load в файл/БД → визуализация в Streamlit) в один оркестрируемый pipeline с логированием и retry. |
| 85–90 | Подведение итогов курса | Обзор пройденного материала, рекомендации по дальнейшему изучению (тестирование данных, CI/CD для дата-пайплайнов, дата-каталоги). |

**Демонстрация:** строим простой pipeline из 3 задач (extract → transform → load) как обычные функции, затем оборачиваем их в Prefect-flow (`@task`/`@flow`), добавляем retry на шаг extract и логирование — показываем граф выполнения и логи.
