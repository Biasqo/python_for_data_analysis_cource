# PySpark: распределённые вычисления

## Концепции распределённых вычислений

### Зачем Spark, если есть Polars?

```
        Данные помещаются в RAM одной машины (< 100 ГБ)?
                          │
          ┌──── Да ───────┴─────── Нет ────┐
          ▼                                ▼
   Polars или pandas             Данные распределены по кластеру?
   (занятия 7–9)                           │
                               ┌── Да ─────┴──── Нет ──┐
                               ▼                       ▼
                    PySpark (или Dask)         Нужно сначала поднять кластер:
                                               AWS EMR, GCP Dataproc, Databricks
```

### Одна машина и кластер

```
 ОДНА МАШИНА (pandas, Polars)         КЛАСТЕР (Spark)
 ────────────────────────────         ────────────────────────────────
 ┌──────────────────────┐             ┌────────┐ ┌────────┐ ┌────────┐
 │ все данные в RAM     │             │ узел 1 │ │ узел 2 │ │ узел 3 │
 │ ограничены её объёмом│             │ часть 1│ │ часть 2│ │ часть 3│
 └──────────────────────┘             └────────┘ └────────┘ └────────┘
 Масштабирование: купить машину       Масштабирование: добавить узлы
 побольше (дорого, предел есть)       (данные растут — узлов больше)
```

### Архитектура Spark

```
┌───────────────────────────────────────────────┐
│               DRIVER (ваша программа)         │
│   SparkSession → строит DAG → планировщик     │
└────────────────────────┬──────────────────────┘
                         │ раздаёт задачи
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
    ┌───────────┐  ┌───────────┐  ┌───────────┐
    │ Executor 1│  │ Executor 2│  │ Executor 3│
    │ [Партиция1]│ │ [Партиция2]│ │ [Партиция3]│
    │ [Партиция4]│ │ [Партиция5]│ │ [Партиция6]│
    └───────────┘  └───────────┘  └───────────┘
          │              │              │
          └──────────────┴──────────────┘
                         │ результаты возвращаются драйверу
```

```
┌────────────┬──────────────────────────────────────────────────┐
│ Понятие    │ Что это                                          │
├────────────┼──────────────────────────────────────────────────┤
│ Driver     │ ваша программа: строит план, координирует работу │
│ Executor   │ процесс (JVM) на узле кластера, выполняет задачи │
│ Partition  │ кусок данных — единица параллелизма              │
│ DAG        │ граф зависимостей между операциями               │
│ Shuffle    │ перераспределение данных между узлами —          │
│            │ самая дорогая операция                           │
└────────────┴──────────────────────────────────────────────────┘
```

### Локальный режим (для занятия)

```
 Кластер:                         Локальный режим:
 Driver ─► Executor на узле 1     ┌─────────────────────────────┐
        ─► Executor на узле 2     │ Driver + Executors          │
        ─► Executor на узле 3     │ в ОДНОМ процессе            │
                                  │ задачи идут по ядрам машины │
                                  └─────────────────────────────┘
 Логика и API одинаковые — поэтому локально удобно учиться.
```

### Партиции и параллелизм

```
 Таблица (1 млн строк)
        │ делится на партиции
        ▼
 ┌─────┬─────┬─────┬─────┐
 │ П1  │ П2  │ П3  │ П4  │   ← по 250 тыс. строк
 └──┬──┴──┬──┴──┬──┴──┬──┘
    ▼     ▼     ▼     ▼
  ядро1 ядро2 ядро3 ядро4     ← каждая партиция обрабатывается
                                 независимо и параллельно

 Правило: число одновременных задач ≤ число свободных ядер.
 Слишком мало партиций → ядра простаивают.
 Слишком много (на малых данных) → накладные расходы на планирование.
```

### Ленивые вычисления

```
 pandas (eager):                     Spark (lazy):
 ───────────────                     ─────────────
 операция 1 ──► результат            трансформация 1 ─┐
 операция 2 ──► результат            трансформация 2 ─┼─► ПЛАН (DAG)
 операция 3 ──► результат            трансформация 3 ─┘      │
 (каждый шаг считается сразу)                                │
                                          действие ──────────┘
                                          (запуск всего плана)
```

```
┌───────────────────────────────┬────────────────────────────────┐
│ ТРАНСФОРМАЦИИ                 │ ДЕЙСТВИЯ                       │
│ (ленивые, строят DAG)         │ (запускают выполнение DAG)     │
├───────────────────────────────┼────────────────────────────────┤
│ select, filter / where        │ show      — показать строки    │
│ withColumn, drop              │ count     — число строк        │
│ orderBy / sort                │ collect   — все строки на      │
│ dropDuplicates                │             driver (опасно!)   │
│ groupBy + agg, join           │ first, take — первые строки    │
│                               │ write     — сохранить в файл   │
└───────────────────────────────┴────────────────────────────────┘

 Аналогия: трансформации — рецепт, действие — поставить блюдо в духовку.
```

### Узкие и широкие трансформации

```
 УЗКИЕ (без shuffle)                  ШИРОКИЕ (со shuffle)
 ───────────────────                  ────────────────────
 Каждая выходная партиция             Выходная партиция зависит
 зависит от ОДНОЙ входной             от НЕСКОЛЬКИХ входных

 П1 ──► П1'                           П1 ──┐     ┌──► П1'
 П2 ──► П2'                           П2 ──┼─────┼──► П2'
 П3 ──► П3'                           П3 ──┘     └──► П3'
                                      (данные пересылаются по сети)
 filter, select, withColumn           groupBy, join, orderBy

 Быстро: данные остаются на          Дорого: сериализация, сеть,
 своём узле                          десериализация
```

### Схема: определить автоматически или задать явно

```
 inferSchema (автоопределение)            Явная схема
 ─────────────────────────────            ───────────────────────────
 Spark читает файл ДВАЖДЫ:                Spark читает файл ОДИН раз
   1-й проход — угадать типы              Типы заданы вами:
   2-й проход — загрузить данные            имя столбца + тип + допускает ли
                                            пустые значения (nullable)

```

### Базовые операции — что делает каждая

┌───────────────┬──────────────────────────────────────────────────────┐

├───────────────┼──────────────────────────────────────────────────────┤

### Действия — что показывают

```
┌───────────────┬──────────────────────────────────────────────────────┐
│ Действие      │ Что возвращает                                       │
├───────────────┼──────────────────────────────────────────────────────┤
│ show          │ первые строки в виде таблицы (можно не обрезать      │
│               │ длинный текст)                                       │
│ count         │ количество строк                                     │
│ first / take  │ одна строка / первые N строк                         │
│ printSchema   │ дерево схемы: столбцы, типы, nullable                │
│ describe      │ статистика: count, mean, stddev, min, max            │
│ collect       │ ВСЕ строки на driver  ⚠ только для малых данных      │
└───────────────┴──────────────────────────────────────────────────────┘
```

### Почему collect опасен

```
 Executors (терабайты данных)
   [П1] [П2] [П3] [П4] ... [П1000]
     │    │    │    │         │
     └────┴────┴────┴─────────┘
                │   collect
                ▼
        ┌───────────────┐
        │ DRIVER        │   Память driver ограничена (единицы ГБ) →
        │ (4–16 ГБ RAM) │   OutOfMemoryError
        └───────────────┘

 Безопасно:  show(N) · take(N) · limit(N) перед сбором · запись в файл
```

### withColumn: виды преобразований

```
┌────────────────┬─────────────────────────────────────────────────┐
│ Вид            │ Пример смысла                                   │
├────────────────┼─────────────────────────────────────────────────┤
│ Арифметика     │ сумма × 1,2 → сумма с НДС                       │
│ Условие        │ если > 1000 → «крупная»;                        │
│ (when/otherwise│ иначе если > 100 → «средняя»; иначе → «малая»   │
│  — аналог where│ (условия проверяются сверху вниз)               │
│  из numpy)     │                                                 │
│ Строки         │ убрать пробелы → нижний регистр                 │
│ Дата           │ текст «2024-05-17» → дата → год, месяц          │
│ Пропуски       │ пустая сумма → 0; пустая категория → «неизв.»   │
└────────────────┴─────────────────────────────────────────────────┘
```

```
 Условная логика «when ... otherwise»:

        сумма > 1000 ?
          │
   ┌─ Да ─┴─ Нет ─┐
   ▼              ▼
 «крупная»    сумма > 100 ?
                  │
           ┌─ Да ─┴─ Нет ─┐
           ▼              ▼
       «средняя»       «малая»
```

### groupBy: разбить → посчитать → собрать

```
  Исходные строки                 Shuffle: строки с одним ключом
  на разных узлах                 собираются в одной партиции
 ┌─────────┐ ┌─────────┐         ┌───────────────────────────┐
 │ Север   │ │ Юг      │         │ Север: все строки Севера  │
 │ Юг      │ │ Север   │  ──►    │ Юг:    все строки Юга     │
 │ Север   │ │ Юг      │         └───────────┬───────────────┘
 └─────────┘ └─────────┘                     ▼
                                    агрегация внутри каждой группы
                                             ▼
                              ┌──────────────────────────────┐
                              │ регион │ выручка │ ср_чек │...│
                              └──────────────────────────────┘
```

Набор агрегаций из лабораторного примера:

```
 сумма  ──► сумма         → «выручка»
 сумма  ──► среднее       → «ср_чек»
 строки ──► количество    → «кол_сделок»
 сумма  ──► максимум      → «макс_чек»
 клиент ──► число разных  → «уник_клиентов»

 Каждой агрегации даётся своё имя результата (alias).
```

### Оконные функции

```
 groupBy:                              Окно (window):
 строки СВОРАЧИВАЮТСЯ в одну на        строки ОСТАЮТСЯ, к каждой
 группу                                добавляется вычисленное значение

 регион │ сумма                        регион │ сумма │ ранг │ нараст. итог
 ───────┼──────                        ───────┼───────┼──────┼─────────────
 Север  │ 500                          Север  │ 500   │  1   │  500
 Север  │ 300   ──►  Север: 800        Север  │ 300   │  2   │  800
 Юг     │ 200        Юг:    200        Юг     │ 200   │  1   │  200

 Окно задаётся двумя вещами:
   • partitionBy — внутри каких групп считаем (регион)
   • orderBy     — в каком порядке строки идут внутри группы
```

### Join: соединение таблиц

```
 ТРАНЗАКЦИИ                            КЛИЕНТЫ
 ┌────┬───────────┬──────┐             ┌───────────┬─────────┬──────────┐
 │ id │ клиент_id │ сумма│             │ клиент_id │ имя     │ сегмент  │
 ├────┼───────────┼──────┤             ├───────────┼─────────┼──────────┤
 │  1 │   101     │  250 │             │   101     │ Иванов  │ VIP      │
 │  2 │   102     │ 1200 │             │   102     │ Петрова │ Стандарт │
 │  3 │   101     │   89 │             │   103     │ Сидоров │ VIP      │
 └────┴───────────┴──────┘             └───────────┴─────────┴──────────┘
              │                                     │
              └────────── ключ: клиент_id ──────────┘
                                │
                                ▼
                ┌────┬───────────┬──────┬─────────┬──────────┐
                │ id │ клиент_id │ сумма│ имя     │ сегмент  │
                └────┴───────────┴──────┴─────────┴──────────┘
```

```
 Когда ключи называются по-разному, условие соединения
 записывается явно: «столбец слева = столбец справа».

   транзакции.клиент_id  ═══  клиенты.id_клиента

 При таком условии ОБА столбца-ключа остаются в результате
 (в отличие от соединения по общему имени ключа, где ключ один).
```

### Два способа соединить таблицы в Spark

```
 ОБЫЧНЫЙ JOIN (с shuffle)                 BROADCAST JOIN (без shuffle)
 ────────────────────────                 ────────────────────────────
 Большая А        Большая Б               Большая А        Маленькая Б
  узел1 узел2      узел1 узел2             узел1  узел2         │
    │     │          │     │                 ▲      ▲          │ копия
    └──┬──┴────┬─────┴─────┘                 │      │          │ рассылается
       ▼ shuffle по ключу ▼                   └──────┴──────────┘ на все узлы
   обе таблицы пересылаются                 Каждый узел соединяет свою часть А
   по сети, чтобы строки с                  с ЛОКАЛЬНОЙ копией Б
   одним ключом оказались рядом
                                            + нет передачи большой таблицы
 Медленно, дорого                           − Б должна помещаться в память
                                              каждого executor
```

```
 Как выбрать:

   Одна из таблиц маленькая (до сотен МБ)?
          │
   ┌─ Да ─┴─ Нет ─┐
   ▼              ▼
 broadcast     обычный join (Spark сам выберет стратегию)

 Типичный случай: большая таблица фактов + маленькие справочники
 (клиенты, продукты) → справочники рассылаем.
```

### SQL-интерфейс

```
 DataFrame ──► регистрация как временное представление (view) ──► имя в SQL
                                                                     │
 SQL-запрос (текст) ◄──────────────────────────────────────────────┘
        │
        ▼
 результат — снова DataFrame (с ним можно продолжать цепочку)
```

```
 Что поддерживает SQL в Spark:
   SELECT · WHERE · GROUP BY · ORDER BY · JOIN
   подзапросы · CTE (WITH ... AS) · оконные функции (LAG, RANK, ...)
```

Правила записи для кириллицы:

```
 ┌──────────────────────────┬────────────────────────────────────┐
 │ Что                      │ Как писать                         │
 ├──────────────────────────┼────────────────────────────────────┤
 │ Имена столбцов кириллицей│ в обратных кавычках                │
 │ Имена представлений      │ проще латиницей (transactions)     │
 │ и псевдонимов таблиц     │ и короткие псевдонимы (t, c)       │
 └──────────────────────────┴────────────────────────────────────┘
```

Пример логики запроса «месячная динамика выручки» (CTE + окно):

```
 Шаг 1 (CTE): сгруппировать выручку по месяцам
        │
        ▼
   месяц   │ выручка
   ────────┼────────
   янв     │ 1000
   фев     │ 1200
   мар     │ 1100
        │
        ▼
 Шаг 2: для каждого месяца взять выручку ПРЕДЫДУЩЕГО (функция LAG)
        │
        ▼
   месяц │ выручка │ пред_месяц │ рост, %
   ──────┼─────────┼────────────┼────────
   янв   │ 1000    │ null       │ null
   фев   │ 1200    │ 1000       │ +20,0
   мар   │ 1100    │ 1200       │ −8,3
```

### SQL и DataFrame API — это одно и то же

```
 SQL-запрос  ─────┐
                  ├──► Catalyst ──► ОДИН И ТОТ ЖЕ физический план
 DataFrame API ───┘

 Выбор — вопрос удобства:
   SQL           — привычен аналитикам, удобен для сложных запросов
   DataFrame API — легче собирать программно, тестировать по частям
```
