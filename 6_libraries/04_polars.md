# Polars: современная альтернатива pandas

#### Ограничения pandas

```text
1. Однопоточность - pandas не использует несколько ядер CPU
2. Лишние копии - многие операции создают промежуточные DataFrame в памяти
3. GIL - Python Global Interpreter Lock ограничивает параллелизм
4. Строки хранятся как Python-объекты - медленно и дорого по памяти
```

#### Дерево решений: pandas или Polars?

```
Размер данных < 1M строк?
├── Да → pandas (проще, больше учебников)
└── Нет → Размер > RAM или нужна скорость?
           ├── Да → Polars (lazy API) или PySpark (кластер)
           └── Нет, но нужна скорость → Polars (eager API)

Другие факторы:
- Команда знает только pandas? → pandas
- Нужна интеграция с ML (sklearn, PyTorch)? → pandas (или конвертация)
- Новый проект, нет legacy-кода? → рассмотрите Polars
```

### Как используются ядра процессора

```
pandas (одно ядро занято, остальные ждут):

  ядро 1  [██████████████████████████████]  100 %
  ядро 2  [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]    0 %
  ядро 3  [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]    0 %
  ядро 4  [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]    0 %

Polars (работа делится между всеми ядрами):

  ядро 1  [██████████]  
  ядро 2  [██████████]   → то же время работы ÷ число ядер
  ядро 3  [██████████]     (в идеальном случае)
  ядро 4  [██████████]
```

> Ускорение зависит от числа ядер. На машине с 1-2 ядрами разница будет небольшой; «в 5-15 раз» характерно для обычного многоядерного ноутбука.

### Как проверить, сколько ядер работает

```
Способ 1: во время расчёта открыть монитор системы
          (htop / Диспетчер задач) и смотреть на загрузку ядер.

Способ 2: сравнить процессорное время и реальное время операции

          ядер задействовано  ≈  процессорное время
                                 ───────────────────
                                 реальное время

          ≈ 1  → одно ядро (pandas)
          > 1  → несколько ядер (Polars)
```

### Eager: каждая операция выполняется сразу

```
 таблица ──► операция 1 ──► ТАБЛИЦА 1 ──► операция 2 ──► ТАБЛИЦА 2 ──► ...
                            (в памяти)                     (в памяти)

 Каждый шаг — результат сразу. Удобно для исследования,
 но Polars не видит запрос целиком и не может его улучшить.
```

Основные eager-операции:

```
┌──────────────────┬────────────────────────────────────────────────┐
│ Задача           │ Как это выражается                             │
├──────────────────┼────────────────────────────────────────────────┤
│ Выбрать столбцы  │ select                                         │
│ Отфильтровать    │ filter + условие над столбцами                 │
│ Добавить столбец │ with_columns (результат — НОВАЯ таблица)       │
│ Отсортировать    │ sort (по умолчанию по возрастанию)             │
│ Переименовать    │ rename (старое имя → новое имя)                │
└──────────────────┴────────────────────────────────────────────────┘
```

### Lazy: сначала план, потом выполнение

```
 таблица ─► [lazy] ─► фильтр ─► новый столбец ─► сортировка ─► выбор
                          │
                          ▼
                 ┌──────────────────┐
                 │  ПЛАН ЗАПРОСА    │   ← ничего не посчитано,
                 │  (только схема)  │     просто записан порядок шагов
                 └────────┬─────────┘
                          │  можно посмотреть план (explain)
                          ▼
                 ┌──────────────────┐
                 │  ОПТИМИЗАТОР     │   ← Polars переставляет и
                 │                  │     упрощает шаги
                 └────────┬─────────┘
                          │  collect — «выполнить!»
                          ▼
                    РЕЗУЛЬТАТ (таблица)
```

### Что делает оптимизатор

```
БЕЗ оптимизации                        С оптимизацией
────────────────                       ──────────────
читать ВСЕ столбцы файла               читать ТОЛЬКО нужные столбцы
        │                                      │       (projection pushdown)
        ▼                                      ▼
считать новый столбец                  отфильтровать строки сразу
для ВСЕХ строк                                 │       (predicate pushdown)
        │                                      ▼
        ▼                              считать новый столбец
отфильтровать                          только для оставшихся строк
        │                                      │
        ▼                                      ▼
    результат                              результат

Результат одинаковый, работы выполнено меньше.
```

### Eager и Lazy — сравнение

```
┌─────────────────────┬──────────────────────┬──────────────────────┐
│                     │ Eager                │ Lazy                 │
├─────────────────────┼──────────────────────┼──────────────────────┤
│ Когда выполняется   │ Сразу                │ При collect          │
│ Оптимизация запроса │ Нет                  │ Да, целиком          │
│ Чтение файла        │ read_csv             │ scan_csv             │
│ Когда подходит      │ Исследование,        │ Pipeline, большие    │
│                     │ небольшие данные     │ данные               │
└─────────────────────┴──────────────────────┴──────────────────────┘
```

### Выражения — сердце Polars

Выражение описывает *что сделать со столбцом*, а не *как пройти по строкам*.

```
        ссылка на       преобразование         имя результата
         столбец
            │                  │                      │
            ▼                  ▼                      ▼
        ┌────────┐       ┌────────────┐          ┌──────────┐
        │ «сумма»│  ──►  │  × 1,2     │   ──►    │ сумма_с_ │
        │        │       │            │          │   ндс    │
        └────────┘       └────────────┘          └──────────┘

 Несколько выражений в одной операции выполняются пареллельно.
```

Виды выражений:

```
┌─────────────────────┬──────────────────────────────────────────────┐
│ Вид                 │ Пример смысла                                │
├─────────────────────┼──────────────────────────────────────────────┤
│ Арифметика          │ сумма × 1,2 → «сумма с НДС»                  │
│ Строки              │ категория → нижний регистр                   │
│ Условие             │ если сумма > 1000 → «крупная», иначе «малая» │
│ Дата                │ текст «2024-05-17» → тип «дата»              │
│ По типу столбцов    │ «все дробные столбцы» → округлить до 2 знаков│
└─────────────────────┴──────────────────────────────────────────────┘
```

Условное выражение — аналог where из numpy:

```
        условие
           │
     ┌─ Да ┴ Нет ─┐
     ▼            ▼
  «крупная»    «малая»      → результат записывается в новый столбец
```

### Сравнение pandas и Polars

```
┌────────────────────┬──────────────────────────┬──────────────────────────┐
│ Задача             │ pandas                   │ Polars                   │
├────────────────────┼──────────────────────────┼──────────────────────────┤
│ Фильтрация         │ булева маска по таблице  │ filter + выражение       │
│ Новый столбец      │ присвоить столбцу        │ with_columns             │
│                    │ (меняет таблицу на месте)│ (возвращает новую)       │
│ Группировка        │ groupby                  │ group_by + набор         │
│                    │ + agg по названиям       │ именованных агрегаций    │
│ Выбор столбцов     │ список имён в скобках    │ select                   │
│ Изменяемость       │ Изменяемый DataFrame     │ Неизменяемый DataFrame   │
│ Индекс строк       │ Есть                     │ Нет                      │
│ Режимы             │ Только eager             │ Eager и lazy             │
└────────────────────┴──────────────────────────┴──────────────────────────┘
```

### Groupby: разбить → посчитать → собрать

```
  Исходная таблица продаж            Группы по (регион, категория)
 ┌────────┬───────────┬─────┐        ┌─ Север / Книги ───────┐
 │ регион │ категория │ сумма│        │ 120, 80, 300          │
 ├────────┼───────────┼─────┤  ──►   ├─ Север / Еда ─────────┤
 │ Север  │ Книги     │ 120 │        │ 50, 70                │
 │ Север  │ Еда       │  50 │        ├─ Юг / Книги ──────────┤
 │ Юг     │ Книги     │ 200 │        │ 200, 90               │
 │  ...   │   ...     │ ... │        └───────────────────────┘
 └────────┴───────────┴─────┘                  │
                                                ▼ несколько агрегаций сразу
                         ┌──────────────────────────────────────────────┐
                         │ регион│ категория│ выручка│ ср_чек│ ...      │
                         └──────────────────────────────────────────────┘
```

Набор агрегаций из лабораторного примера:

```
 сумма  ──► сумма          → «выручка»
 сумма  ──► среднее        → «ср_чек»
 сумма  ──► количество     → «кол_сделок»
 сумма  ──► максимум       → «макс_чек»
 клиент ──► число разных   → «уник_клиентов»

 ВАЖНО: каждой агрегации даётся своё имя результата.
 Если две агрегации одного столбца остаются без имени,
 получатся два столбца с одинаковым названием → ошибка.
```

### Виды join

```
 LEFT JOIN                        INNER JOIN
 ┌───────┐                        ┌───────┐
 │ ██████│░░░░░░░                 │   ░░░░│░░░░░░░
 │ ██████│░░░░░░░                 │   ░░░░│░░░░░░░
 └───────┘                        └───────┘
 Все строки левой таблицы;        Только строки, у которых
 нет пары справа → пустые         есть пара в обеих таблицах
 значения (null).
```

Когда ключи называются по-разному, указывают отдельно имя ключа в левой и в правой таблице:

```
 левая таблица: «клиент_id»  ═══ соответствует ═══  правая таблица: «id»
```

(Столбец с таким именем должен действительно существовать в правой таблице.)

### Почему Polars быстрее на группировке

```
 pandas                              Polars
 ──────                              ──────
 вся таблица (5 млн строк)           вся таблица (5 млн строк)
        │                                   │
        ▼                           ┌───┬───┼───┬───┐
 одно ядро обрабатывает            ▼   ▼   ▼   ▼
 строки подряд                   часть часть часть часть
        │                         1     2     3     4   ← по ядрам
        ▼                           └───┴───┬───┴───┘
     результат                              ▼
                                   объединение результатов
```

### Типичные ловушки при переходе с pandas

```
 ┌───┬──────────────────────┬────────────────────────────────────────┐
 │ № │ Привычка из pandas   │ Как правильно в Polars                 │
 ├───┼──────────────────────┼────────────────────────────────────────┤
 │ 1 │ Менять таблицу       │ Polars неизменяем: операция возвращает │
 │   │ «на месте»           │ новую таблицу — результат нужно        │
 │   │                      │ присвоить переменной                   │
 ├───┼──────────────────────┼────────────────────────────────────────┤
 │ 2 │ Бояться              │ Такого предупреждения нет: операции    │
 │   │ SettingWithCopy      │ всегда возвращают новый объект         │
 ├───┼──────────────────────┼────────────────────────────────────────┤
 │ 3 │ Ждать порядок групп  │ group_by НЕ гарантирует порядок —      │
 │   │ после groupby        │ нужен явный sort по ключу группы       │
 ├───┼──────────────────────┼────────────────────────────────────────┤
 │ 4 │ Искать строку        │ Индекса строк нет — всегда явный       │
 │   │ по индексу           │ фильтр по значению столбца             │
 ├───┼──────────────────────┼────────────────────────────────────────┤
 │ 5 │ Агрегировать один    │ Каждой агрегации — своё имя            │
 │   │ столбец дважды       │ результата, иначе имена совпадут       │
 └───┴──────────────────────┴────────────────────────────────────────┘
```
